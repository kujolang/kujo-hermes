# Verification

Run tests in a Python environment with `jsonschema` and, for host checks, Hermes's normal dependencies.

- `python3 -m unittest discover -s tests -v`: configuration, profiles, definitions, schema validation, trust, symlinks, missing dependencies, approval binding/consumption, subprocess failure, timeout, cancellation, output bounds, redaction and receipt tampering. Hardening regressions also cover escaped output and changed-limit receipt retrieval, retained schema-failure evidence, bounded diagnostics, nested artifact paths, failed runtime probes and proxy-independent loopback transport.
- `python3 scripts/real-tools.py --sources ROOT --kujo BINARY`: runs canonical tools in a temporary Git workspace. Checks output fields, Scout manifests, Eval pass/fail totals, Spec validity, PackWrite phase count, Loop verdict and all receipt hashes. A test callback supplies approvals; this script does not test the Hermes host.
- `python3 scripts/service-tools.py --sources ROOT --kujo BINARY`: starts a real temporary Watchdog service with SQLite and cleans up its process.
- `PYTHONPATH=HERMES_SOURCE python3 tests/hermes_e2e.py --sources ROOT --kujo BINARY --isolation host`: copies the plugin into a fresh temporary Hermes home, loads through the actual PluginManager, invokes registered tools through native approval hooks, verifies denial then approved mutation, runs a multi-tool engineering workflow, reads receipts, handles failure and unloads. Repeat with `--isolation in_process`.
- `--interactive` replaces deterministic test decisions with operator input. The automated CLI callback supplies test decisions, not human consent. Add `--live-model gemma4:31b-cloud` with that installed Ollama model to test a real LLM conversation. Evidence records native Hermes deferred discovery (`tool_search`, `tool_describe`, `tool_call`), actual ShipCheck output and verified receipt retrieval.
- `hermes plugins doctor .` and `hermes plugins validate . --install-deps`: official host discovery and marketplace admission checks. If a dependency download fails, report it separately from manifest and runtime validation.
- `python3 scripts/measure.py`: measured local initialization/discovery/inspection latency and serialized tool-surface bytes; no estimated token savings.
- `python3 scripts/install-sources.py --destination ROOT --only shipcheck`: real official source install verified at an exact commit. No upstream code is executed by the installer.

Development used the installed Loop harness and actual PackWrite manifest compiler. The first Loop iteration caught a quoting error in the gate command. Simplifying that command fixed the gate. PackWrite compiled a hand-written offline manifest through its documented fake-response interface and validated all seven phase files. `evidence/packwrite.log` identifies the provider as fake; it is not presented as model-generated work. A separate live PackWrite init using Ollama `gemma4:31b-cloud` generated 20 files across 13 phases and passed canonical validation (`evidence/live-packwrite.json`).

The repository stores selected execution evidence. Temporary service databases, source checkouts, runtime binaries and Hermes homes are not shipped. Local receipts record product artifact hashes; the repository retains selected summaries. The readiness document states which operations are verified, blocked or untested.
