# Kujo Hermes — evidence you can use

Three possible films: a release rescue led by ShipCheck; a two-command install followed by developer benefits; or an audit trail followed backward from a receipt. This version uses installation and benefits because a Hermes user should know how to start and why to care.

1. Paired Kujo and Hermes logos establish the native integration.
2. Native discovery establishes the breadth of tools and the need for evidence.
3. Real installer output and the two exact commands show how to start. Requires Hermes, Kujo and Git; accept Hermes's prompts. Network waiting is condensed.
4. PackWrite's native evidence view shows seven present phases. Benefit: organized instructions for the agent. This is a seeded pack summary, not a new generation.
5. Spec's native evidence view shows the validated contract. Benefit: clear acceptance criteria.
6. The original free local model recording shows the actual approval. Benefit: the developer decides what executes.
7. Eval's own native evidence view shows two passing checks. Benefit: repeatable verification, not a promise that the whole product is correct.
8. ShipCheck's own view shows warnings. Benefit: find gaps before release.
9. Scout's own view shows the repository scan. Benefit: orient work in the code. Other tools retain prerequisites.
10. The actual receipt view shows command, approval and hashes. Benefit: a handoff another developer can trace.
11. Paired logos return with “Trust at the speed of AI” and “Install Kujo Hermes today.” Hold the public repository URL.

Each named tool has a distinct matching source clip. All screen widths remain visible. Do not use one Eval screen as generic filler. Native viewer files are derived from actual tool executions; they are not model-written conversation messages. The original Qwen3.5 4B approval is the only model-run excerpt in this edit.
